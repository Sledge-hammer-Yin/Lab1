# Lab1 运行说明

## 1 打开正确的目录

在文件资源管理器进入本次下载的 `AAE4203-S12627_合并版/Lab1`，在地址栏输入 `powershell` 并回车。
以下所有相对路径均以 `Lab1` 为当前目录。路径可以含中文和空格。

```powershell
python --version
python -m pip install -r requirements.txt
```

`numpy` 是数值程序唯一的必需第三方依赖。Matplotlib 和 Cartopy 均不是必需依赖。
若系统没有 `python`，可尝试 `py -3`，或使用自己环境内的 Python 完整路径。

## 2 跑通课件历史示例

```powershell
python WLSE_spp.py --reference dataset/NAV-HPPOSECEF.csv
```

输出位置：

| 文件 | 内容 |
| --- | --- |
| `outputs/example/G01_owndata.csv` | 标准五列 ECEF，时间按0.1秒网格输出 |
| `outputs/example/solution_details.csv` | 保留原始 OBS 时间精度的坐标、钟差和有效测量数 |
| `outputs/example/omitted_epochs.csv` | 未求解历元及原因；正常示例只有表头 |
| `outputs/example/summary.json` | 求解数量和可选的接收机参考比较 |

预期：186/186，2D RMSE 37.9107584162 m，3D RMSE 51.0428443069 m。
参考坐标原单位为厘米，`iTOW` 为毫秒。程序按时间匹配，未按行号硬拼。
这些误差是相对接收机解的差异；接收机解不是测量真值。

检查提交格式（原来的“一个文件名”命令仍支持，以下增加实际观测时间检查）：

```powershell
python tools/check_submission.py outputs/example/G01_owndata.csv --epoch-file dataset/epochs.csv
```

这是历史示例演示文件，不是任何学生组的实测成果。

补充验证：若把示例原始 OBS/NAV 交给新 `rinex2csv.m` 重新转换，再以 `gps` 模式运行，可求解113/186历元；73历元在当前GPS筛选条件下省略。与接收机参考比较的2D/3D差异RMS约15.393/82.106 m。这条新GPS路线与原历史CSV的输入和模型不同，不要求得到课件数值。

## 3 跑通 UrbanNav 基准

不安装 MATLAB 的快速路线：

```powershell
python WLSE_spp.py --mode gps --input-dir benchmark/preprocessed_gps --output-dir outputs/benchmark --submission G01_benchmark.csv
python tools/check_submission.py outputs/benchmark/G01_benchmark.csv --week 2158 --epoch-file benchmark/preprocessed_gps/epochs.csv
```

程序只读取测量 CSV、卫星坐标、改正量和 OBS 时间。真值无需提供。
`summary.json` 的 `coverage_percent` 为求解历元占这份 OBS 历元的比例；不是定位准确度。

需要重做 RINEX 转换时，打开 MATLAB，在 `Lab1` 当前目录运行：

```matlab
rinex2csv('benchmark/UrbanNav-HK-Deep-Urban-1.ublox.f9p.obs', ...
          'benchmark/UrbanNav_20210521_multiGNSS_clean.nav', ...
          'outputs/benchmark_inputs');
```

转换不弹出绘图窗口。该函数使用 MatRTKLIB 的本机 MEX 文件，不需要 Mapping Toolbox 绘图。
转换完成后：

```powershell
python WLSE_spp.py --mode gps --input-dir outputs/benchmark_inputs --output-dir outputs/benchmark_regenerated --submission G01_benchmark.csv
python tools/check_submission.py outputs/benchmark_regenerated/G01_benchmark.csv --week 2158 --epoch-file outputs/benchmark_inputs/epochs.csv
```

GPS 基线条件：GPS L1、15°高度角、15 dB-Hz最低信号强度、广播星历、模型大气改正、TGD、地球自转修正。每个失败历元单独省略，不复制上一位置。
转换函数仅为此教学包的 RINEX3/GPS 基线服务，其他接收机和数据需重新检查。

## 4 处理自己采集的数据

1. 用 u-center 记录 UBX，并备份原始文件。
2. 用 RTKCONV 将 UBX 转成配套 OBS/NAV；记录所用软件版本和设置。
3. 在 MATLAB 调用 `rinex2csv`，参数分别为自己的 OBS、NAV 和输出文件夹。

```matlab
rinex2csv('mydata/my.obs','mydata/my.nav','outputs/own_inputs');
```

4. 用 Python 求解，并将 G01 换成自己的组号：

```powershell
python WLSE_spp.py --mode gps --input-dir outputs/own_inputs --output-dir outputs/own --submission G01_owndata.csv
python tools/check_submission.py outputs/own/G01_owndata.csv --epoch-file outputs/own_inputs/epochs.csv
```

5. 与 RTKPOST 和接收机参考解做时间对齐后的比较。不要把这三者之一直接称作真值。
6. 按课程要求准备图、报告、代码说明及 AI 使用说明。

## 6 遇到问题时

| 提示或情况 | 处理 |
| --- | --- |
| 找不到 CSV | 核对当前目录和 `--input-dir`；不要混入旧目录根部的4548历元CSV |
| 缺少 numpy | 用执行程序的同一个 Python 运行 `-m pip install -r requirements.txt` |
| MATLAB 找不到 gt | 确认 `matRTKLIB/` 与 `rinex2csv.m` 同级；函数会自行加路径 |
| MEX 无法加载 | 核对 MATLAB/操作系统与第三方预编译文件是否兼容，参考工具箱 README |
| 少于4颗可用卫星 | 本历元可能被省略，查看转换摘要和 `omitted_epochs.csv`；不能补造位置 |
| 基准坐标只有格式通过 | 仍需 TA 服务器计算误差；本包没有真值，不能本地判断排名 |
| 输出与课件不同 | 确认是 historical 模式和随包186历元输入；新GPS基线不承诺复现历史数值 |

`legacy/` 存放旧脚本供对照。旧脚本存在固定文件路径、绘图依赖及不同数据混用风险，正常运行使用根目录的新入口。
